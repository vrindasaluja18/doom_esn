# AGENTS.md

Guidance for agents working in this repository.

## What this repo is

`doom-esn` is a CPU-only ViZDoom agent plus a measured study of one question: given a fixed
resident-memory budget `B` bytes, how should the agent store its past so it still plays? The
research program is in `docs/RESEARCH_PROGRAM.md`; the maths ledger (with
`derived` / `tested` / `measured` / `unverified` tags) is in `docs/MATHS.md`.

## Environment

- Python 3.10-3.13. Install: `pip install -e ".[dev,doom,perception]"` (CPU only).
- Optional groups: `doom` (vizdoom), `perception` (torch, torchvision, pillow),
  `bench` (matplotlib, ripser), `ppo` (stable-baselines3), `dev` (pytest, ruff, mypy).
- The pretrained perception arm downloads MobileNetV3-Small weights once (~10 MB); it never
  trains them. Everything runs headless on CPU.

## Benchmark protocol (do not slow it down again)

`bench/memory_budget.py` is **collect-once, fit-all-arms-offline**:

1. collect ONE latent dataset per seed under a uniform-random policy and cache it to
   `docs/results/latents/*.npz` (keyed by scenario/seed/episodes/max-steps);
2. replay every memory back-end over those *same* cached latents and solve the linear
   fitted-Q readout in pure numpy — no engine, no CNN per arm;
3. evaluate greedily on held-out seeds.

The encoder is the bottleneck (~3.5 ms/frame single-frame, ~0.4 ms/frame batched), so
re-rolling the engine and CNN for every `(arm, seed, round)` made one scenario take 30-45 min
and lose everything if the process was killed. Each `(backend, seed)` row is appended to
`docs/results/memory/<scenario>.jsonl` as soon as it is computed, and `--resume` skips rows
already present, so a run survives a restart. Do not reintroduce per-arm rollouts.

`docs/results/latents/` is gitignored (regenerable data); the `.jsonl` checkpoints are also
gitignored; only the final `<scenario>.json` evidence files are committed.


## Conventions

- src layout; frozen dataclasses; strict YAML config (unknown keys rejected); seed everything.
- `ruff` + `mypy` + `pytest` must pass; tests run with warnings as errors.
- Every maths claim needs a named test or a stored measurement (see the MATHS ledger).
- Label claims `derived` / `tested` / `measured` / `unverified`, as `docs/MATHS.md` does.
- Do not commit generated artifacts: `_vizdoom.ini` (regenerated by vizdoom) and
  `docs/results/latents.npy` are gitignored. Benchmark JSON under `docs/results/` IS committed
  (it is the evidence), and so is the demo GIF.
- `bench/memory_budget.py --perception mobilenet --seeds 3` takes ~15 minutes on CPU. Run long
  jobs in the background and poll the log.

## The research object (do not break it)

- `src/doom_esn/memory.py` is the object of study. Every back-end must report `state_nbytes()`
  (the budgeted resident state) and `fixed_nbytes()` (fixed tables) separately. Do not merge
  the two: the whole point is that the resident state can be tiny while a fixed table is large.
- `src/doom_esn/readout.py` (`LinearQ`) is solved by fitted Q-iteration, not searched. Keep it
  solved; CMA-ES search noise was the bottleneck this repo deliberately removed.
- Perception is frozen and pretrained on purpose. Do not train it here.

## Memory back-ends (how to add one)

Implement `reset()` and `step(u) -> feature`, plus `state_nbytes()` and `fixed_nbytes()`. If the
back-end wraps another (e.g. a quantiser over a reservoir), call the base's `reset()`/`step()`
and add the base's fixed bytes. Register it in `bench/memory_budget.py:build_backends`.

## Results hygiene

- Report return with a standard error and the number of seeds. A gap within one standard error
  is "equal-or-better", not "better".
- Prefer orientation-agnostic AUC power `max(AUC, 1-AUC)` when a feature may point either way.
- State failures plainly. `docs/topology.md` is a documented negative; keep it that way rather
  than dressing it up.
